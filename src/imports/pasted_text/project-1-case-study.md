=== OVERVIEW ===
Spectra's Inspection module lets surveyors review, annotate and report on a site 
from a single screen. It joins the site's structure, its media and its geography — 
a hierarchical tree, gallery and list views, and an interactive map — so an 
observation never leaves the context it came from.

=== THE PROBLEM ===
Heading: Inspection was four tools pretending to be one workflow
Body: Surveyors captured media in the field, then reassembled the story somewhere 
else. Nothing carried from capture to finding to report. Mapping the current 
workflow surfaced four consistent breakpoints.
Then a 2x2 grid of cards, each with a number (01–04), a title and one line:
  01 Media loses its location — Once images left the drone, nothing tied them 
     back to the asset or coordinates they came from.
  02 Finding costs more than analysing — Surveyors spent longer hunting for the 
     right file in a drive than assessing what was in it.
  03 Findings didn't persist — Observations lived in loose notes and screenshots, 
     so insight from one inspection rarely reached the next.
  04 Reports were rebuilt from scratch — Every handoff meant reassembling the 
     inspection in a separate tool, delaying time-sensitive decisions.

=== PROCESS ===
Heading: No existing feature to learn from
Body: The workflow only existed outside the product, so I went to where it was 
actually happening.
Numbered horizontal step strip (4 steps, animate in staggered):
  01 Interviewed surveyors and reviewers
  02 Mapped the current manual workflow end to end
  03 Benchmarked the tools they were using instead
  04 Aligned scope with product and engineering
Then a two-column list under the sub-heading "What the mapping showed":
  Media arrived unstructured — Bulk uploads landed as flat folders with no 
  relationship to the site's zones or assets.
  Location was lost at import — Coordinates sat in file metadata, but nothing 
  surfaced them, so surveyors rebuilt the site map from memory.
  Two different ways of looking — Surveyors alternated between scanning visually 
  for defects and auditing status across the full set. Never both at once.
  Reporting was the biggest time sink — Every report was reassembled by hand, 
  long after the inspection ended.

=== THE DECISIONS ===
Heading: Six decisions, one workspace
Alternating full-width image + text rows. Image reveals with a mask wipe, text 
slides in from the side.
  Start from the site, not the files — The tree mirrors the real hierarchy 
  (tower → phase → asset) with live counts at every level, so surveyors know how 
  much sits in a zone before opening it and never lose their place.
  Every image knows where it came from — The map isn't a separate tab. Selecting 
  a file drops a pin; selecting a pin surfaces the file. The link between what was 
  seen and where it was seen never breaks.
  Two ways of looking, one set of files — Gallery for spotting a defect visually, 
  list for auditing status across hundreds of files. A toggle keeps both in the 
  same place instead of forcing a choice.
  Coverage without opening a file — Filters for type, asset, defect, tag and date 
  narrow 1,246 files to the ones that matter. The questions that lived in a side 
  spreadsheet get answered in place.
  Findings that stay attached — Annotating a defect directly on the image turns a 
  vague description into precise evidence, bound to the asset and its coordinates. 
  It survives into the next inspection.
  Reporting starts where the inspection ended — Findings reach other teams from 
  the same screen that produced them. No rebuilding the story elsewhere.
